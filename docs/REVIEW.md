**MorphMatch publication review — 11 October 2026**

**Deployment update — 15 October 2026:** the public website is live at [morphmatch.vercel.app](https://morphmatch.vercel.app). The account release is staged with production settings after eight hosted email/account checks and six staged desktop/Android account checks passed. Public activation awaits resolution of the iCloud sender's storage limit; the owner waived inbox confirmation. Current deployment and verification details are in [the launch record](LAUNCH.md).

The follow-up finishing phases and expanded mobile verification are recorded in [Production readiness — 12 October 2026](PRODUCTION_READINESS.md). The findings and test counts below describe the original review.

The review covered the application routes, components, matching engine, bundled athlete data, persistence, Supabase authentication and database permissions, dependencies, build configuration and CI. Existing local database/setup changes were retained. This work prepares the repository for deployment; no public deployment was created.

The highest-impact findings were vulnerable runtime dependencies and excessive database privileges. Next.js was upgraded from 16.2.10 to 16.4.0, React to 19.3.0, and compatible dependencies were refreshed in the lockfile. Supabase's default table grants had left authenticated users with `TRUNCATE`, which bypasses row-level ownership rules. Migration `0004` revokes inherited privileges and grants only `SELECT`, `INSERT` and `DELETE`. Migration `0003` validates new saved-comparison payloads without deleting existing records.

**Verification evidence**

The account review also reproduced a corrupt session cookie that could make public pages return errors. The session proxy now recovers from malformed cookies, preserves valid sessions during temporary authentication outages and retains cache protection when refreshing cookies. Password-recovery callbacks preserve the configured public origin or validated local hostname, preventing verification cookies from becoming separated from the browser.

`npm test` exercises data integrity, matching and unit conversion, filter/selection behavior, comparison geometry and metadata, photo loading and attribution validation, saved JSON, safe authentication redirects, session-cookie recovery, deployment origins, robots and sitemaps. `npm run test:accounts` uses disposable users on the existing local Supabase stack, verifies signup/sign-in/save/delete, two-user ownership isolation, payload constraints and exact table privileges, and cleans up without resetting the database. The bundled dataset contains 350 athletes across four sports.

The browser suite runs against a production server on desktop and mobile. It covers missing accounts, persistent preferences, corrupt or blocked storage, incomplete metric and imperial input, filtering, shared comparison URLs and browser history, keyboard selection, mobile navigation, viewport fit, security headers and automated WCAG A/AA checks. A separate local-account run covers sign-in return paths, saved Numbers views, account isolation, failed-deletion recovery and an actual recovery email followed by password change and sign-in. Third-party photo outages are mocked in deterministic browser tests; a live Commons metadata lookup was also checked.

**Launch requirements and remaining limits**

- Set `SITE_URL` to the public origin before the production build. Matching and browsing can be published with accounts disabled.
- For accounts, use a hosted Supabase project's public URL/key, apply all four migrations in order, configure the production Site URL and callback allow-list, and test confirmation and password recovery emails. Enable Google only after configuring its provider. Supabase's [built-in SMTP is intended for testing](https://supabase.com/docs/guides/auth/auth-smtp), so public registration requires a configured sender.
- The athlete dataset is a historical reference snapshot. Structure, uniqueness and plausibility checks pass, but individual records lack citations and all 350 measurements were not independently source-verified. League/career labels should not be presented as current. Refresh and cite the dataset if that is part of the launch promise.
- Production dependencies pass `npm audit --omit=dev`. The full audit retains five high-severity package reports from one development-only `braces` advisory through ESLint's dependency chain. The [upstream advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) currently lists no patched version. The application does not pass visitor input to that development tooling. Keep dependency alerts enabled and update when a compatible upstream fix is available.
- ESLint 9 is [past its support period](https://eslint.org/version-support/). Next.js's currently bundled React and accessibility plugins still declare peer support through ESLint 9. The compatible setup passes lint; move to ESLint 10 when that dependency chain supports it.
- Hosted Google OAuth, public SMTP delivery and final domain configuration require the chosen production accounts and domain; local checks cannot certify those external settings. Wikimedia photos remain optional and depend on service availability and supported licence metadata.
