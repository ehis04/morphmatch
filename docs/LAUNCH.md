# Launch record — 16 October 2026

Matching, athlete browsing, comparisons, sharing, email/password accounts and saved comparisons are live at **https://morphmatch.vercel.app**. Public signup is enabled, email confirmation is required and Google sign-in is disabled. The canonical domain now serves the accounts-enabled Production release.

**Release update — 16 October 2026:** Gmail SMTP on port 587 replaced the capacity-limited iCloud sender, resolving that launch blocker. All six desktop/Android account checks and eight email/account checks passed on the canonical public domain. Signup, resend and recovery requests were accepted, and actual sent-token PKCE callbacks completed. Independent cleanup verification found zero test users/saves and zero total users/saves at completion. Eight Gmail email/account checks also passed on the protected preview on 15 October. Auth/SMTP acceptance and completed sent-token callbacks do not establish inbox receipt. The owner explicitly waived that check, and inbox delivery remains unverified.

The deployment build runs `npm run build:production`: environment validation, lint, types, regressions, production dependency audit and optimized build. GitHub Actions additionally checks source formatting and runs browser checks. Local `prepare:production` checks formatting before the guarded build. Vercel rewrites `vercel.json` before cloud builds, so formatting validation runs against the original source in CI rather than that generated file. These are separate services; the current setup does not make Vercel wait for GitHub's browser job.

Node.js is pinned to major 22 in the package, lockfile, `.nvmrc` and hosting settings. Generated Vercel/Supabase state is excluded from source-quality checks so linking a project does not break local verification.

The function region is pinned to `dub1` in `vercel.json` so automatic Git deployments stay near the Ireland database; a one-off CLI deployment region does not persist to later Git builds.

## Operations and remaining limits

Production account variables, canonical deployment and public signup are activated. Keep email confirmation required and monitor account errors, SMTP capacity and service usage as real traffic arrives. Gmail is the current sender; a dedicated transactional provider remains an optional operating choice as usage grows. No email-provider subscription has been purchased.

Native share-sheet behavior and email-app handoff remain unverified on physical phones; a brief manual phone check is optional. This is a responsive web deployment with no separate native iOS/Android app package or offline service worker.

A custom website domain and Google sign-in remain optional; Google is disabled until its provider is configured and verified. An hourly and manually runnable GitHub Actions availability check probes public pages, `/login`, `/saved` and metadata, using the repository variable `PRODUCTION_SITE_URL`. Those probes check availability; they do not send email or exercise an authenticated session. GitHub notification preferences control who receives workflow-failure notifications; delivery has not been certified. Scheduled Actions can be delayed and do not provide continuous monitoring. Vercel Hobby and Supabase Free limits remain operational constraints, and the Free database plan may pause after inactivity. Continuous database availability, automatic backups and monitoring with guaranteed response still require an owner-approved service/operating choice. No paid plan, backup service or monitoring subscription was purchased or enabled.

The repository's existing dataset-sourcing and development-tooling limitations remain in [the original review](REVIEW.md). Earlier implementation and local/mobile verification evidence is in [production readiness](PRODUCTION_READINESS.md).
